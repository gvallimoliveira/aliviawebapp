# Insight signal architecture
- Clinic patient-list totals and the existing period report render only in the summary registry entry; the list stays record-focused. Preserve original counts/report math and clinic permissions; status charts remain in the existing Insights analytics, not duplicated in Patients.

- Appointment reads exclude personal commitments before counting in cards and RPCs. Notes explicitly linked to commitments cannot become care sessions; unlinked notes and legacy NULL service types remain valid. Preserve Agenda records and existing scope/authorization.

- Smart insights live in `src/components/dashboard/insights/` backed by scoped RPCs (`get_patient_churn_risk`, `get_patient_load_alerts`, `get_reassessment_due`, `get_steps_phase_overview`, `get_reactivation_candidates`, `get_clinic_therapist_stats`, `get_discharge_predictions`, `get_clinic_patient_concentration`, `get_patient_adherence_scores`); all deterministic, clinic/solo scoped (solo = clinic_id IS NULL), no AI credits. Pain and readiness signals come from readiness check-ins only — pain diary and internal messages are never metric inputs (few patients use them). Realized sessions count from completed slots OR same-day session notes (`synthesizeNoteSessions`), so unclassified agendas never empty the metrics; flare-up is the latest check-in pain ≥ 2 above the 30-day average (3+ check-ins). Discharge prediction blends check-in pain (40), STEPS phase (30), 4-week load progress (15) and current readiness (15).

- Operational growth insights (frequency gap, referral, leakage, late cancel, owner dependence, capacity bottleneck) are pure functions in `managementMetrics.ts` over the scoped `useManagementData` rows; `prescribed_weekly_frequency`/`referral_source`/`rooms_count` feed them. Late-cancel uses trigger `status_changed_at` (legacy/time-less slots stay "unknown"; window = cancellation date). Leakage names: latest session, else patient registry. Bottleneck: occupancy + saturation; solo shows occupancy only.
- Clinic team payouts are pure in `payouts.ts` (shared price resolver → service deduction → service override else professional rule; monthly fixed and month adjustments independent of volume), stored in owner/admin-only `clinic_compensation`/`clinic_payout_adjustments`; one engine feeds the Insights card and the payout PDF.
